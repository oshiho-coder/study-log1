# 模写サイト⑧：Travel Blog（ブログサイト）

## サイト概要
旅行系ブログサイトを想定した模写コーディング。  
記事一覧・ピックアップ記事・サイドバー（プロフィール／ランキング／アーカイブ）・固定ヘッダー・フッターまでを実装し、  
**HTMLの意味構造設計**、**Flexによるレイアウト管理**、**fixedヘッダー時のレイアウト調整**を重点的に学習した。

## サイト種類
ブログサイト（個人ブログ想定）

## ページ構成
- Header（サイトロゴ／グローバルナビ）
- Pick up（注目記事）
- 記事一覧（メインカラム）
- サイドバー
  - プロフィール
  - ランキング
  - アーカイブ
- Footer（About／Menu／Youtube／コピーライト）

## 対応端末
- PC
- スマートフォン（レスポンシブ対応）

## 使用技術
- HTML5
- CSS3
- Flexbox
- Google Fonts
- RESS（CSSリセット）

## 実装内容
- headerを`position: fixed`で固定し、`z-index`で前面表示
- fixedヘッダーによる被り対策として`body`に`margin-top`を指定
- メインエリアとサイドバーをFlexで2カラムレイアウト
- 記事メタ情報（日付・カテゴリ）を横並び表示
- Archiveリストに上下ボーダーを用いた区切り線を実装
- READ MOREリンクにホバー時の下線アニメーションを実装
- フッター内リストを用途別にFlex／columnで制御

## 講師からの指摘
- fixedヘッダーの高さが変わるとレイアウトが崩れるため、`main`ではなく`body`側で余白を管理する方が安全
- `.main__item ul { display: flex; }` の指定により、HTML内の他の`ul`まで横並びになる可能性がある
  → クラスを付与してピンポイント指定する必要がある
- Archiveの区切り線が上下で二重に見える可能性があるため、`border-top`と`border-bottom`の使い分けを意識する
- サイトロゴはリンクにして、トップページに戻れる導線を作るべき

## 詰まった点
- fixedヘッダーとメインコンテンツの位置関係の理解が曖昧だった
- `ul { display: flex; }` の影響範囲を深く考えずに指定してしまった
- ボーダーが重なって見える原因を最初は把握できなかった
- フッター内のリスト構造が増えたことで、CSSの指定範囲が混乱した

## 学んだこと
- fixed要素を使う場合、レイアウト全体への影響を考慮する必要がある
- CSSは「広く効かせる」のではなく「狭く正確に当てる」ことが重要
- 見た目が崩れたときは、構造（HTML）と責務（CSS）を切り分けて考える
- ボーダーは上下両方に指定すると視覚的に二重線になりやすい
- ナビゲーションやロゴは、ユーザー導線としての役割を持つ

## 今後の改善点
- fixedヘッダーの高さをCSS変数で管理する設計にする
- Archive部分を`dl`構造にするなど、意味構造の改善を検討する
- hover時のアニメーションに`transition`の緩急を追加する
- SP表示時の余白・文字サイズの最適化
- BEMを意識したクラス設計の整理
